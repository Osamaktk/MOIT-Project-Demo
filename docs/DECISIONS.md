# Decisions

- **2026-10-17 — Preserve the supplied architecture as the project source.** The attached `ARCHITECTURE.md` is copied into this repository unchanged so implementation and review use a stable, versioned specification.
- **2026-10-17 — Phase 0 is the initial delivery.** The workspace was empty, so implementation begins at the first phase and will not introduce later-phase product screens before the foundation is in place.
- **2026-10-17 — Backend settings load `.env` from the repository root.** This keeps a single configuration file for both processes and makes paths independent of the shell's current working directory.
- **2026-10-17 — Demo login uses one documented synthetic password for the eight seeded role personas.** This makes Phase 0 role acceptance repeatable; it is demo-only and should be replaced before any non-demo use.
- **2026-10-17 — Pin bcrypt below 4.1 with Passlib 1.7.4.** The newest bcrypt release broke Passlib's backend compatibility in the local environment; bcrypt 4.0.1 hashes and verifies the demo credentials cleanly.
- **2026-10-17 — Keep saved Register filters in browser storage per signed-in user.** The demo has a single local installation; this keeps saved views simple without adding an unrequested server-side preference service.
- **2026-10-17 — SQLAlchemy metadata and Alembic are used together.** The schema stays portable while schema changes remain explicit and reproducible; startup does not silently create/alter tables.
- **2026-10-17 — Dashboard KPI counts and drill-downs share the same service filters.** This keeps the Friday totals auditable against the exact source records, with overdue actions restricted to approved Register entries.
- **2026-10-17 — Transaction stage counts are centralized in configuration.** Stage labels and the seven generic values can be replaced in one place when the demonstration deck is updated.
- **2026-10-17 — Use a stage-count table as an accessible chart fallback.** Dashboard stage totals remain inspectable and drillable without relying on chart pointer interaction.
- **2026-10-17 — Keep model identifiers in environment configuration and verify them against the live OpenRouter catalogue.** This avoids tying the demo to stale model names and lets local/cloud zones change through configuration.
- **2026-10-17 — Missing or suspended tool-switch rows fail closed.** Deployment must seed approved tool switches before AI calls are allowed; an uninitialized switch is treated as unavailable.
- **2026-10-17 — Keep the minutes presentation cache opt-in and transcript-specific.** Only a prior successful synthetic meeting extraction may be reused, its SHA-256 transcript fingerprint must match, and policy/kill-switch denials bypass the cache. A distinct assurance run identifies cache use.
- **2026-10-17 — Health endpoints report readiness without secrets or side effects.** The public AI health endpoint checks configured extraction model/provider state and installed STT/vector capabilities; it does not initialize a vector database or make provider calls.
- **2026-10-17 — Bound admin-created passwords to bcrypt's byte limit.** The schema rejects values over 72 UTF-8 bytes so account creation cannot silently truncate password material.
- **2026-10-17 — Keep presentation rate limits in process.** The app is specified to run as one local API process; login and AI routes receive per-client sliding-window limits, and deployment with multiple workers must replace this with a shared limiter.
- **2026-10-17 — Keep local semantic embeddings optional for clean demo setup.** `EMBEDDING_MODEL` enables a multilingual sentence-transformers model and `backend/requirements-embeddings.txt` keeps the ML runtime out of the base install. Blank model configuration retains the deterministic offline fallback; Chroma collections are keyed by embedding model so different vector spaces do not mix.
- **2026-10-17 — Track long-running meeting processing in the database and execute with FastAPI background tasks.** Job status and coarse graph-stage progress are queryable and streamable over SSE. The local single-process demo has no durable external queue, so a server restart can interrupt a running task.
